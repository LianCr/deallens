# DealLens — 3-minute demo script

Voice-over for a screen recording. About 430 spoken words ≈ 3 minutes
at a relaxed pace. `[screen]` lines are what to click; only the quoted
text is spoken. Record against the live site
(<https://deallens-xi.vercel.app>) in a clean browser profile at 1280 px
wide.

**Before recording**

- Open `/api/health` once: note whether `listingSearch` is `live` or
  `demo-fallback` — use the matching line in section 2.
- Have a second tab on the GitHub Actions page for the latest green run.
- Chrome DevTools → Command menu → "Disable JavaScript" ready for
  section 4.

---

## 1. The problem (0:00–0:25)

`[screen]` Home page, hero visible.

> "When you buy a used car, the dealer knows the market and you don't.
> DealLens is a web app I built to answer one question: is this
> actually a good deal? The rule I designed it around is: the AI
> narrates, the math decides. Every number on screen comes from a
> deterministic pricing engine, and every number cites where it came
> from."

## 2. Listing analyzer (0:25–1:15)

`[screen]` Click **Analyze listing**. Enter Honda, Civic, 2022, price
24,500, mileage 42,000. Click **Analyze this listing**.

> "Here I enter a listing: a 2022 Civic at
> twenty-four five with forty-two thousand miles. The server searches
> for comparable listings, normalizes them, and throws out the ones
> that don't match — different year, way more miles, no price."

`[screen]` Scroll to **Comparable listings**, then **Why some listings
were excluded**.

If `/api/health` said `live`:
> "Each comparable links to the actual page it came from."

If it said `demo-fallback`:
> "This deployment is running without a search key, so the
> comparables are a labeled demo dataset — the badge says so. The
> pipeline is identical either way."

`[screen]` Scroll to **Where this ask lands** and **Trust Trace**.

> "This is the verdict: where the asking price sits against those
> comparables, as a percentile. And this is the Trust Trace — a
> receipt that shows every step of the math, generated by the same
> function that produced the verdict, so the explanation can't drift
> from the answer."

## 3. Grounded AI (1:15–1:50)

`[screen]` Scroll to **AI research report**.

> "Only after the math is done does a language model get involved.
> It receives a facts block built from the evidence, and its output is
> validated: if it cites a listing ID that isn't in the evidence, that
> citation is stripped. And if the model is down, you still get the
> full deterministic result — the AI is optional, the answer isn't."

## 4. Deal dashboard, with JavaScript off (1:50–2:30)

`[screen]` Open `/deal/honda/2022/civic?quote=24500`. Show the verdict,
distribution chart, drag the quote slider once.

> "Every result also has a shareable dashboard. The whole state is in
> the URL, so you can send this link to someone and they see exactly
> what you see."

`[screen]` Disable JavaScript in DevTools, reload.

> "Now I've turned JavaScript off and reloaded. The verdict, the
> receipt, and the charts are all still here, because they're
> server-rendered. The slider still works too — it falls back to a
> plain form the server answers."

## 5. Engineering (2:30–3:00)

`[screen]` Switch to the GitHub Actions tab, expand the latest green run.

> "Under the hood it's Next.js and TypeScript, with a GraphQL gateway
> over the NHTSA and EPA government APIs. Every pull request runs unit
> tests, end-to-end tests in three browsers plus a no-JavaScript run,
> an accessibility scan in light and dark mode, and Lighthouse and
> bundle-size budgets against the production build. That's DealLens —
> thanks for watching."
